# 알약케어 계정 메뉴 및 증상 리포트 UI 설계

## 목적

로그인 이후 사용자가 알약케어 홈으로 이동하고, 우측 상단 사용자 메뉴를 통해 마이페이지·비밀번호 수정·로그아웃 흐름으로 이동할 수 있는 프론트엔드 화면과 데이터 구조를 마련한다.

이번 작업은 화면 흐름과 목업 데이터만 구현한다. 실제 인증, 회원 정보 저장, S3 업로드·Presigned URL 발급·권한 검증은 로그인 및 회원가입 담당 팀원과 백엔드 작업에서 연결한다.

## 범위

### 포함

- 응급실 관련 라우트, 내비게이션 메뉴, 홈 진입 카드, 시설 목업 데이터 및 UI 제거
- 로그인 성공 후 알약케어 홈(`/`)으로 이동하는 화면 흐름
- 인증 상태에 따른 우측 상단 사용자 메뉴 토글
- 마이페이지(`/mypage`)
- 비밀번호 수정(`/password`)
- 로그아웃 확인 모달
- 증상 기록 리포트 카드와 문서 이미지 뷰어
- 화면 흐름을 검증하는 React Testing Library 테스트

### 제외

- 실제 로그인·회원가입 API
- 토큰, 세션, 인증 가드의 서버 검증
- 회원 정보와 비밀번호의 영구 저장
- 실제 S3 업로드 및 Presigned URL 발급
- 증상 문서의 신규 생성·수정·삭제 API

## 라우팅 및 사용자 흐름

```text
/login
  └─ 로그인 성공 → /
       └─ 우측 상단 사용자 메뉴
            ├─ 마이페이지 → /mypage
            ├─ 비밀번호 수정 → /password
            └─ 로그아웃 → 확인 모달 → 확인 시 /login
```

- 로그인 화면의 제출은 현재 목업 동작으로 처리한다.
- 로그인 성공 시 전역 목업 사용자 상태를 설정하고 `replace` 이동으로 홈 화면을 표시한다.
- `/mypage`와 `/password`는 목업 인증 상태가 없으면 `/login`으로 이동한다.
- 로그아웃 모달은 확인, 아니오, 바깥 영역 클릭, `Escape` 키로 닫힘 동작을 제공한다.
- `facilities` 경로는 더 이상 화면을 제공하지 않으며 와일드카드 홈 이동으로 처리한다.

## 컴포넌트 경계

- `AuthProvider`: 현재 로그인한 목업 사용자와 로그인·로그아웃·비밀번호 수정 상태를 제공한다.
- `UserMenu`: 우측 상단 토글과 마이페이지·비밀번호 수정·로그아웃 항목을 제공한다.
- `LogoutConfirmModal`: 로그아웃 의사를 확인하고 취소·바깥 클릭·Escape 동작을 처리한다.
- `MyPage`: 사용자 요약 정보와 증상 리포트 카드를 표시한다.
- `SymptomReportCard`: 리포트 요약을 카드로 표시하고 이미지 보기 동작을 전달한다.
- `SymptomDocumentModal`: 선택한 리포트의 문서 이미지 URL을 표시한다.
- `PasswordChangePage`: 현재 비밀번호·새 비밀번호·새 비밀번호 확인 입력과 목업 검증 상태를 표시한다.

인증·사용자 관련 컴포넌트는 기존 프론트엔드 컨벤션에 따라 `src/components/user/`에 둔다. 페이지 컴포넌트는 `src/pages/`에 둔다.

## 목업 데이터 구조

```js
const MOCK_USER_PROFILE = {
  id: 'pill-user',
  name: '홍길동',
  gender: 'female',
  birthDate: '1998-04-12',
}

const SYMPTOM_REPORTS = [
  {
    id: 'symptom-report-1',
    createdAt: '2026-08-19T14:30:00+09:00',
    symptoms: ['두통', '발열'],
    severity: '중간 정도',
    summary: '오늘 오후부터 두통과 발열이 시작되었습니다.',
    documentImageUrl: 'https://example.com/presigned/symptom-report-1.png',
  },
]
```

`documentImageUrl`은 추후 백엔드가 반환하는 S3 Presigned URL을 그대로 대입하는 경계다. 현재 화면에서는 실제 외부 S3 요청을 만들지 않으며, 로컬에서 확인 가능한 목업 이미지 URL 또는 placeholder를 사용한다.

## UI 규칙

- 인증된 상태에서만 사용자 메뉴를 노출한다.
- 사용자 메뉴는 데스크톱 헤더와 모바일 헤더 모두 우측 상단에서 접근할 수 있다.
- 로그아웃은 즉시 실행하지 않고 `로그아웃할까요?` 확인 모달을 거친다.
- 비밀번호 수정은 세 입력값이 모두 채워지고 새 비밀번호와 확인 값이 일치할 때만 제출할 수 있다.
- 증상 리포트 카드는 증상·작성 시각·정도·요약을 보여준다.
- 리포트 카드 선택 시 이미지 뷰어 모달을 열고 `documentImageUrl`을 이미지 `src`로 사용한다.
- API 미연결 상태와 목업 데이터임을 화면에서 알 수 있도록 안내 문구를 유지한다.
- 고정 헤더·메뉴·모달은 기존 반응형 토큰과 키보드 포커스 스타일을 따른다.

## 접근성 및 오류 경계

- 사용자 메뉴 토글은 `aria-expanded`와 `aria-controls`를 제공한다.
- 모달은 `role="dialog"`, `aria-modal="true"`, 제목 연결을 사용한다.
- 모달 바깥 클릭은 overlay 자체를 클릭한 경우에만 닫힌다.
- 이미지가 로드되지 않으면 대체 문구와 placeholder 상태를 표시한다.
- 실제 인증 실패·Presigned URL 만료·권한 오류는 이번 범위에서 서버 연동 시점에 처리한다.

## 검증 기준

- 응급실 관련 링크·텍스트·라우트가 주요 화면에 남아 있지 않다.
- 로그인 성공 시 홈으로 이동하고 사용자 메뉴가 표시된다.
- 메뉴의 세 항목이 정확한 경로 또는 모달 흐름으로 동작한다.
- 로그아웃 모달의 확인·아니오·바깥 클릭·Escape 동작이 동작한다.
- 비밀번호 수정 페이지의 필수 입력 및 불일치 상태가 동작한다.
- 마이페이지에 증상 리포트 카드가 표시되고 카드 선택 시 목업 문서 이미지가 보인다.
- `npm run test -- --run`과 `npm run build`가 성공한다.
