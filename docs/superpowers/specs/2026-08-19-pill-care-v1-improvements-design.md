# 알약케어 ver 1.0 UI 개선 설계

## 목적

기존 정적 알약 식별 화면을 아픈 사용자가 빠르게 사용할 수 있는 흐름으로 확장한다. 사용자는 먼저 증상을 고르고, 집에 있는 알약의 앞면과 뒷면 예시 이미지 영역을 눌러 사진 입력 방식을 선택한 다음, API 연결 전 Mock 결과에서 대표 약품과 복용 전 주의사항을 확인한다.

이번 단계는 브라우저 프론트 UI에 한정하며, 실제 의약품 식별·사용기한 확인·복용 기록 저장은 수행하지 않는다.

## 확정 흐름

1. `/identify/image`에서 증상 Chip을 복수 선택한다.
2. 앞면·뒷면 예시 이미지 영역을 누르면 `촬영하기`, `앨범에서 선택하기`, `파일 탐색기에서 선택하기` 메뉴를 열고, 선택한 파일은 브라우저 메모리에서만 미리보기한다.
3. 하나 이상의 증상을 선택하면 `알약 찾기` 버튼이 활성화된다.
4. 버튼을 누르면 React Router `state`로 증상과 Mock 약품 ID를 `/search/results`에 전달한다.
5. 결과 화면 직접 접근 또는 새로고침에서는 `두통`, `발열`을 Mock fallback으로 사용한다.
6. `복용하기`는 즉시 완료하지 않고 `복용 전 확인해주세요` 모달을 연다.
7. 사용자가 확인하면 저장 대신 `복용 기록이 저장되었습니다` 상태만 화면에 표시한다.

## 응급실 전화 기능 제외

이번 후속 UI에서는 응급실 전화 기능을 제공하지 않는다. 전역 Floating Button과 응급의료기관 카드의 전화 버튼·전화번호 노출을 제거하고, `/facilities`의 SVG 지도와 기관 정보 목업만 유지한다.

## 데이터 및 경계

- 증상 옵션은 20개 고정 Mock 목록이다.
- 대표 약품은 기존 `prime-tablet` 데이터이며 사용기한은 `사용기한 확인 불가`로 표시한다.
- 사진은 서버로 전송하지 않고 `URL.createObjectURL()`로만 처리한다.
- 홈은 최근 확인한 약품 목록 없이 식별·증상·기관 진입만 제공한다.
- 실제 API, Gemini 분석, 인증, 저장, Spring Boot, Nginx는 포함하지 않는다.

## 접근성 및 반응형 원칙

- 증상 선택은 `aria-pressed`로 선택 상태를 전달한다.
- 모든 Chip, 버튼, 사진 선택 영역은 최소 44px 터치 영역을 갖는다.
- 사진 선택 메뉴는 예시 이미지 영역 클릭 후에만 표시하며, 초기 화면에는 예시 알약 이미지를 유지한다.
- 복용 모달은 `role="dialog"`, `aria-modal`, 제목 연결, 닫기 버튼, Escape 닫기를 제공한다.
- 모바일은 4열 compact Chip grid와 2열 사진 카드를 사용하며 매우 좁은 폭에서는 사진 카드를 1열로 전환한다.
- 모바일 고정 액션 바가 하단 내비게이션을 가리지 않도록 페이지 하단 여백을 확보한다.
